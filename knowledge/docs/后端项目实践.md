# 后端项目实践（示例资料，可替换为你的真实项目）

## 项目 A：课程管理系统 API

用 FastAPI + Pydantic + SQLAlchemy 做的校内课程管理后端，支持课程查询、选课与冲突检测。

- 接口层：RESTful 设计，GET/POST/PATCH 语义分开；用 Pydantic 模型约束入参，非法请求在进入业务逻辑之前就被挡掉，同时自动生成 `/docs` 交互文档。
- 数据层：MySQL 建表，课程、选课记录、学生三张表用外键约束；按「学期 + 院系」建联合索引优化查询。
- 分层：路由只做参数校验与转发，业务逻辑放在 service 层，数据访问放在 repository 层，方便单独写单元测试。
- 踩过的坑：一开始把 SQL 直接写在路由函数里，同一个查询散落三处，改一个字段要改三遍；后来抽成 repository 层统一维护。
- 技术：Python、FastAPI、Pydantic v2、SQLAlchemy、MySQL、Docker。

个人职责：设计表结构与索引、实现选课冲突检测、补齐离线单元测试。

## 项目 B：数据同步与定时任务

把教务系统导出的表格同步进数据库，每天定时跑一次，并输出差异报告。

- 用定时调度触发任务；执行前后都写日志，失败时保留现场数据不覆盖，方便回看。
- 幂等设计：以「学号 + 学期」作为唯一键，脚本重复跑不会产生重复记录。
- 大文件用流式读取，避免一次性全部载入内存。
- 技术：Python、pandas、SQLite、定时任务、日志告警。

个人职责：设计幂等键、实现差异比对、处理编码与脏数据。

## 项目 C：日志分析与可视化小工具

把服务日志按接口维度聚合，统计 P95 延迟与错误率，输出 Markdown 报表。

- 用 pandas 做分组聚合，matplotlib 出图；报表每天自动生成。
- 收获：先定义清楚指标口径再动手写代码，否则做出的图没人敢拿去用。
- 技术：Python、pandas、matplotlib、Markdown 模板。
