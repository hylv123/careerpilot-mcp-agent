# 基础知识笔记

## 操作系统

进程与线程的区别、上下文切换的成本。IO 密集型任务适合多线程或协程，CPU 密集型要考虑多进程。
在 Python 里，同步阻塞的长任务如果直接放在 Web 框架中，会把请求线程占满，连健康检查都响应不了；正确做法是挪到独立进程或用线程池隔离。

## 计算机网络

HTTP 方法语义：GET 幂等、POST 非幂等，PATCH 用于局部更新。
常见状态码的含义差异很大：200 成功、202 已受理但未完成、404 不存在、429 限流、502 上游故障、503 本服务暂时不可用。
理解 **202 Accepted** 的用途：请求已受理但还没做完，客户端要拿着返回的编号另外去查结果——这正是长任务接口的通行做法。
HTTPS 的证书校验不能随手关掉，否则等于把明文交出去。

## 数据库

索引能加速查询但会拖慢写入，建索引必须看实际查询模式而不是凭感觉。
事务的 ACID；并发下要特别注意幂等——同一个操作重复执行不应该产生重复结果。
连接数是有上限的，长事务会占着连接不释放，进而拖垮整个服务。

## Linux 与 Git

常用命令：`grep`/`awk` 查日志、`ss`/`netstat` 看端口占用、`docker logs` 看容器输出。
Git：提交粒度要小，一次提交只做一件事。
**误提交的密钥即使删掉文件也仍然留在历史里**——正确做法是先去控制台撤销密钥，删除文件并不能补救。
