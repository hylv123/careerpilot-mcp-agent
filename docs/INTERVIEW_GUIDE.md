# CareerPilot 面试讲解指南

## 一分钟介绍

CareerPilot 是一个基于 MCP、LangGraph 和 RAG 的实习求职助手。用户输入岗位 JD 后，系统先用结构化输出提取岗位要求，再从候选人的 FAISS 知识库中检索真实经历；当高相关结果不足时改写查询并补充检索。之后 LangGraph 继续生成带来源的匹配报告、简历要点和面试题，并通过 MCP 工具保存岗位。项目还包含 20 例离线评测、节点和工具级日志，以及模型失败重试和 MCP 降级机制。

## 为什么使用 MCP

直接函数调用适合单体原型，但工具实现会与 Agent 框架紧密绑定。MCP 将工具发现、参数 Schema 和调用方式标准化，Resume、Job、Document 三类能力可以作为独立服务维护，也可以被其他兼容宿主复用。

当前项目使用 stdio，是因为它部署简单、适合本地演示，也避免为了展示协议而过早引入网络鉴权和服务治理。远程 Streamable HTTP 是后续扩展，不是当前已经实现的能力。

## Agentic RAG 体现在哪里

系统不是只执行一次固定检索。它先使用岗位关键词召回，并依据 FAISS 距离判断高相关结果是否充足；不足时让模型把岗位术语改写成更接近个人经历的检索词，再进行第二轮检索和去重合并。

这一实现仍有改进空间：距离阈值依赖 Embedding 模型和知识库分布，后续应使用标注数据校准，并增加关键词召回、重排和 Recall@k 指标。

## LangGraph 的价值

这个场景包含岗位分析、检索、工具调用、报告、简历、面试题和持久化等多个步骤。LangGraph 把步骤和状态显式化，便于查看路径、单独测试节点、记录耗时，并在工具调用后回到 Agent 继续决策。

如果只是一次问答，普通 Chain 更简单；这里选择 Graph 是因为存在状态传递、条件工具路由和多个结构化产物。

## 如何控制幻觉

- 简历要点和面试题都必须返回 `evidence_source`。
- 生成来源必须出现在本轮检索结果中。
- Pydantic 校验输出数量和字段结构。
- 评测脚本检查来源存在性、来源真实性和明显占位文本。
- Prompt 明确禁止虚构经历。

当前方法主要控制“来源字段是否匹配”，还没有证明每个自然语言断言都被原文充分支持。更严格的版本应增加 claim-evidence 对齐和人工抽查。

## 如何做评测

项目使用 10 个真实岗位样例和 10 个改写变体，检查：

- Pydantic 格式是否通过；
- 预期关键词是否覆盖；
- 引用是否存在；
- 引用是否来自本轮证据；
- 是否出现明显占位或虚构项目名；
- 是否发生运行异常。

默认评测关闭 MCP，目的是避免批量评测写入数据库和生成文件。MCP 链路通过单独的 `--with-tools` 冒烟测试验证，面试时应主动说明这一区别。

## 遇到 MCP Server 失败怎么办

工具发现阶段捕获异常并降级为空工具列表，工作流仍可完成基于 RAG 的核心生成。模型调用和工具调用都有日志；岗位保存阶段如果没有 `save_job`，会明确输出“未保存”，不会伪造成功状态。

## 可以继续优化什么

1. 增加 Streamlit 页面和流式输出。
2. 用 BM25 加向量检索实现混合召回，并增加重排。
3. 对检索阈值做数据驱动校准。
4. 增加工具调用、数据库和文档生成的自动化集成测试。
5. 记录 Token、成本、P50/P95 延迟和多次运行稳定性。
6. 为远程 MCP 增加鉴权、超时、限流和健康检查。
